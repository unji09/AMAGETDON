# JPA 학습2 – 3일차
## 연관관계 동작 원리(프록시/LAZY), 생명주기 관리(CASCADE/고아객체), 값 타입 규칙

## 학습 주제
JPA의 내부 동작 원리인 프록시와 지연 로딩을 이해하고,
엔티티의 생명주기를 효율적으로 관리하는 방법과 값 타입의 안전한 설계 규칙을 정리한다.

## 학습 내용

### 1. 프록시(Proxy)와 조회 시점 제어

JPA는 성능 최적화를 위해 실제 엔티티 객체 대신 프록시 객체를 활용한다.

- em.find(): DB를 즉시 조회하여 실제 엔티티 객체를 반환한다.
- em.getReference(): DB 조회를 미루고, 식별자 값만 가진 프록시 객체를 반환한다.

```java
Member member = em.getReference(Member.class, "id1"); // DB 조회 X
member.getName(); // 이 시점에 실제 DB 조회 (초기화)
```

#### 프록시의 특징과 주의 사항

- 프록시 객체는 실제 엔티티 클래스를 상속하여 생성된다.
- 최초 접근 시 한 번만 초기화된다.
- 프록시 객체가 실제 엔티티로 교체되는 것은 아니다.
- 영속성 컨텍스트 종료 후 프록시 초기화 시 LazyInitializationException이 발생한다.

프록시는 연관 엔티티를 항상 조회하지 않기 위해 사용되는 메커니즘이다.

### 2. 로딩 전략: LAZY를 기본으로 설정하는 이유

연관된 엔티티를 어느 시점에 조회할지를 결정하는 전략이다.

- LAZY(지연 로딩):
  연관 엔티티를 프록시로 조회하고, 실제 접근 시점에 DB 조회가 발생한다.
- EAGER(즉시 로딩):
  엔티티 조회 시 연관된 엔티티를 JOIN하여 즉시 함께 조회한다.

LAZY가 기본으로 권장되는 이유는 다음과 같다.

1. 즉시 로딩은 연관관계가 복잡해질수록 실행되는 쿼리를 예측하기 어렵다.
2. JPQL 사용 시 N+1 문제가 발생할 가능성이 높다.

따라서 모든 연관관계는 LAZY로 설정하고,
필요한 경우에만 fetch join이나 엔티티 그래프를 사용하여 조회 범위를 명시적으로 제어한다.

### 3. CASCADE와 orphanRemoval의 사용 조건

CASCADE와 고아 객체 제거는 연관관계 매핑과는 별개로,
엔티티의 생명주기를 부모 엔티티에 종속시키기 위한 기능이다.

- CASCADE:
  부모 엔티티의 저장 또는 삭제 작업을 자식 엔티티에게 전파한다.
- orphanRemoval:
  부모 엔티티의 컬렉션에서 제거된 자식 엔티티를 DB에서도 함께 삭제한다.

사용 조건은 다음과 같다.

- 자식 엔티티가 단일 부모에 의해서만 관리되는 관계일 것
- 자식 엔티티가 독립적으로 사용되지 않을 것

CASCADE = ALL과 orphanRemoval = true를 함께 사용하면
부모 엔티티가 자식의 생명주기를 완전히 관리하게 된다.

### 4. 값 타입 불변 설계의 중요성

값 타입(Value Type)은 식별자가 없으며 엔티티에 종속된다.

값 타입 설계 시 다음 규칙을 따른다.

- Setter를 제공하지 않는다.
- 생성자를 통해서만 값을 설정한다.
- 값 변경이 필요할 경우 새로운 객체를 생성한다.

이를 통해 여러 엔티티가 동일한 값 타입을 공유할 때 발생할 수 있는
부작용(Side Effect)을 방지할 수 있다.

값 타입은 식별자가 없으므로 equals()와 hashCode()를 재정의하여
값 자체를 기준으로 동등성 비교를 수행해야 한다.

### 5. 값 타입 컬렉션의 제약 사항

@ElementCollection으로 매핑된 값 타입 컬렉션은 다음과 같은 제약을 가진다.

- 식별자가 존재하지 않는다.
- 특정 요소 변경 시 관련 컬렉션 데이터를 모두 삭제 후 재삽입한다.

데이터 변경이 잦거나 이력 관리가 필요한 경우에는
값 타입을 엔티티로 승격하여 일대다(OneToMany) 관계로 관리하는 것이 적절하다.

## 요약 정리

| 구분 | 핵심 내용 |
| --- | --- |
| 프록시 / LAZY | 필요 시점에만 DB 조회하여 성능과 쿼리 예측 가능성 확보 |
| EAGER 지양 | 예기치 못한 JOIN과 N+1 문제 방지를 위해 사용하지 않음 |
| 생명주기 관리 | CASCADE, orphanRemoval은 단일 소유자 관계에서만 사용 |
| 값 타입 | 불변 객체로 설계하여 공유로 인한 부작용 방지 |
| 값 타입 컬렉션 | 전체 재삽입 특성으로 인해 엔티티 승격 여부 검토 |

# WebRTC 학습 – 1일차  
## WebRTC 개념 구조와 OpenVidu 기반 실시간 통신 기능 정리

## 학습 주제
브라우저 기반 실시간 통신 기술인 WebRTC의 핵심 구조를 이해하고,  
OpenVidu를 활용해 구현 가능한 기능 범위와 사용 시 필수 고려 사항을 정리한다.

## 학습 내용

### 1. WebRTC의 기본 개념과 특징

WebRTC는 브라우저 간 실시간 미디어 및 데이터 전송을 지원하는 기술이다.  
중앙 서버를 거치지 않고 사용자 간 직접 연결(Peer-to-Peer)을 지향한다.

주요 특징은 다음과 같다.

- Peer-to-Peer 기반 통신  
  미디어 및 데이터가 서버를 경유하지 않고 사용자 간 직접 전송된다.
- 실시간 미디어 스트리밍  
  낮은 지연 시간으로 음성·영상 스트리밍이 가능하다.
- 미디어 외 데이터 전송 지원  
  오디오·비디오뿐 아니라 텍스트 및 바이너리 데이터도 전송할 수 있다.
- 브라우저 자체 지원  
  별도의 플러그인 없이 JavaScript API만으로 사용 가능하다.
- 비교적 낮은 진입 장벽  
  기본적인 Web API 지식으로 구현이 가능하다.

단, 브라우저 환경 및 네트워크 제약으로 인해 연결을 보조하는 추가 단계가 필요하다.

---

### 2. WebRTC 연결을 위한 핵심 구성 요소

WebRTC 연결은 단순히 브라우저 간 접속만으로 이루어지지 않으며,  
연결을 성립시키기 위한 사전 정보 교환 과정이 필요하다.

#### 2.1 Signaling

Signaling은 WebRTC 연결 이전에 필요한 정보를 교환하는 단계이다.  
WebRTC 표준에는 Signaling 방식이 포함되지 않으며, 별도의 서버(WebSocket 등)로 구현한다.

교환되는 주요 정보는 다음과 같다.

- SDP
- ICE Candidate

#### 2.2 SDP (Session Description Protocol)

SDP는 미디어 송수신 방식에 대한 설명 정보이다.

- 지원 가능한 코덱
- 해상도 및 프레임 레이트
- 오디오/비디오 트랙 정보

#### 2.3 ICE Candidate

ICE Candidate는 통신에 사용할 수 있는 IP와 PORT 후보 목록이다.  
네트워크 환경에 따라 여러 후보가 생성된다.

#### 2.4 STUN / TURN 서버

- STUN  
  클라이언트가 자신의 공인 IP와 PORT를 확인하기 위해 사용된다.
- TURN  
  P2P 연결이 불가능한 경우, 미디어를 중계하는 서버 역할을 수행한다.

TURN 서버는 안정성을 높이지만 서버 부하와 비용이 증가한다.

### 3. OpenVidu를 통해 제공되는 주요 기능 영역

OpenVidu는 WebRTC를 직접 구현하지 않고도  
고수준 API로 실시간 통신 기능을 제공하는 플랫폼이다.

#### 3.1 미디어 스트림 제어

OpenVidu는 영상과 음성을 세밀하게 제어할 수 있는 기능을 제공한다.

- 화면 공유  
  웹캠 대신 전체 화면, 특정 창, 브라우저 탭 송출 가능
- 오디오/비디오 트랙 제어  
  사용자별 마이크 및 카메라 On/Off 제어
- 미러링  
  좌우 반전 영상 처리
- 해상도 및 프레임 레이트 조절  
  네트워크 상황에 따라 품질 동적 조정 가능

---

### 4. 상호작용 및 이벤트 기반 기능

단순 화상 통화가 아닌 서비스 형태의 실시간 기능 구현이 가능하다.

- 시그널링 메시지 전송  
  JSON 기반 데이터 교환으로 채팅, 알림, 상태 변경 구현 가능
- 발언자 감지  
  현재 발언 중인 사용자를 감지하여 UI 반영 가능
- 사용자 제어  
  방장 권한을 통한 강제 퇴장, 송출 중단 기능 제공

---

### 5. 실시간 영상 가공 및 특수 효과

OpenVidu는 Kurento Media Server를 활용해 영상 가공 기능을 제공한다.

- 가상 배경 및 배경 흐림 처리
- 텍스트 오버레이 삽입
- 크로마키 처리
- 얼굴 인식 기반 마스크 및 필터 적용

이를 통해 단순 통신을 넘어 시각적 효과를 포함한 서비스 구현이 가능하다.

---

### 6. 녹화 기능

실시간 통신 내용을 서버에 저장할 수 있다.

- COMPOSED 녹화  
  여러 사용자의 영상을 하나의 화면으로 합쳐 저장
- INDIVIDUAL 녹화  
  사용자별 영상 파일을 개별 저장
- 오디오 전용 녹화  
  음성 데이터만 별도 저장 가능

---

### 7. OpenVidu 사용 시 필수 고려 사항

#### 7.1 Docker 기반 실행 환경

OpenVidu는 Docker 환경에서 실행하는 것이 기본 전제이다.

- 로컬 개발 환경 및 서버 배포 환경 모두 Docker 사용
- 설치 및 실행 난이도는 비교적 낮음

#### 7.2 포트 개방 설정

WebRTC는 다수의 포트를 사용하므로 보안 그룹 설정이 중요하다.

- TCP/UDP 443: HTTPS 및 WebSocket 통신
- TCP/UDP 3478: STUN/TURN 서버
- TCP/UDP 40000–57000: 실제 미디어 전송

포트 설정 오류 시 영상 또는 음성만 동작하지 않는 문제가 발생할 수 있다.

#### 7.3 HTTPS 및 도메인 설정

보안 정책상 WebRTC는 HTTPS 환경에서만 정상 동작한다.

- IP 주소 직접 접근 시 카메라/마이크 권한 제한
- 도메인 연결 및 SSL 인증서 필수
- OpenVidu는 SSL 인증서 자동 발급 및 갱신 기능 제공

---

## 요약 정리

- WebRTC는 P2P 기반 실시간 미디어 및 데이터 통신 기술이다.
- 연결 성립을 위해 Signaling, SDP, ICE Candidate 교환이 필요하다.
- OpenVidu는 WebRTC 기능을 고수준 API로 제공한다.
- 미디어 제어, 상호작용, 영상 가공, 녹화 기능을 통합적으로 지원한다.
- Docker, 포트 개방, HTTPS 환경은 필수 전제 조건이다.
